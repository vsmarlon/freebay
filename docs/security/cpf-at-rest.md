# CPF/CNPJ at rest

New CPF/CNPJ writes through `UserDatabaseRepository` use AES-256-GCM ciphertext in the existing `User.cpf` column (`v1:<iv>:<tag>:<ciphertext>`) and a deterministic, keyed HMAC-SHA-256 (`v1:<digest>`) in the existing unique `User.cpfHash` column. No schema change or plaintext fallback was added. `CPF_ENCRYPTION_KEY` and `CPF_HMAC_KEY` are independent base64 encodings of exactly 32 random bytes; never derive one from the other or from `JWT_SECRET`. Missing/invalid keys fail CPF writes and CPF-dependent reads. Authentication and unrelated profile reads suppress unreadable/legacy CPF to `null`; they do not expose or trust stored plaintext. Checkout receives decrypted CPF only through the owner’s dedicated repository path.

The data-export repository decrypts the owner's identifier for their export. `GET /users/me/export` is source-guarded by `@RequireStepUp('export_data')`; runtime journey evidence is not claimed here. Keep these keys in a secret manager, back them up under separate access controls, and do not rotate either key independently: the current reader supports only `v1` under the active key. Rotation requires an owner-approved, auditable re-encryption procedure that retains old-key read access until every row is rewritten and verified; do not simply replace the key.

Existing plaintext rows are intentionally not backfilled or used as a write fallback. New writes check normalized legacy plaintext for duplicates, and the existing unique HMAC constraint arbitrates concurrent new-format duplicates. The `scripts/audit-legacy-cpf.mjs` tool only reports counts and duplicate groups; it never writes or emits CPF values/IDs. It requires `--read-only`, defaults to `freebay_test_db`, and refuses other databases unless `CPF_AUDIT_ALLOW_NONTEST_READ_ONLY=1` is explicitly set. Do not run it against a live database during this change. An owner must resolve duplicate groups and approve a separately controlled backfill before existing legacy accounts regain CPF-dependent operations.

Example (guarded test database only): `node scripts/audit-legacy-cpf.mjs --read-only`. No automatic or live backfill is part of this change.
