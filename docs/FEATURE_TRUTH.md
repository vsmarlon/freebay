# FreeBay feature truth and gap register

**Snapshot:** 2026-10-01, integrated working tree at `c9808b1` plus dirty changes. **Scope:** Flutter app + NestJS controllers, use cases, repositories, Prisma schema, and available tests. This is an implementation audit, **not** a production-readiness certificate or a claim that all these flows have been exercised on a device. `FEATURE_MAP.md` is a route inventory; this document records what those routes actually enable and where a journey stops. Final UX gate and source evidence: [`docs/test-runs/2026-10-01/frontend-ux-finalization/REPORT.md`](test-runs/2026-10-01/frontend-ux-finalization/REPORT.md).

**For agents:** read this before promising, planning, or implementing a product feature. Trace UI → provider/repository → HTTP/socket endpoint → use case → persistence/side effects before changing a status. After a fix, update the affected row with the exact boundary and verification performed; a widget test, a backend test against a synchronized test DB, a real device, and a live provider are different kinds of evidence. Use `frontend/DESIGN.md` for visual rules and `docs/DEVICE_TESTING.md` for device evidence. Existing skill flow diagrams describe intended behavior and may be ahead of the code.

Legend: **wired** = code path on both sides, not runtime-proven; **partial** = important part missing/inconsistent; **missing** = no complete feature path found; **fixed in working tree** = regression reproduced and changed locally, device/provider still unverified.

## Priority queue: comparable user experience, not imitation by feature count

1. **P0 — complete working buying/saving journeys.** Reproduce on Android/iOS and a real backend: save → saved list → unsave from detail → reload/account switch; catalog → cart quantity/stock → payment → signed webhook → final order. Record failures and evidence under `docs/test-runs/` and `docs/device-runs/`. The Android 16 emulator verified only the journey through pending checkout and PaymentSheet launch; no settled payment. Verify test DB and runtime DB separately if a Prisma column is implicated. Then resolve remaining payment, inventory, and state-recovery failures at the shared seam.
2. **P0 — money and fulfillment.** Deliver shipping address capture, quotes/charges, label/tracking/proof, buyer/seller timeline and carrier events before claiming eBay/Mercado Livre delivery parity. Confirm Stripe platform verification, signed webhooks, refund/reversal, payout and reconciliation with provider evidence before claiming real-money readiness. Do not infer fulfillment from `PATCH /orders/:id/ship` alone.
3. **P1 — chat trust and reliability.** Verify typing events cannot escape authorized rooms; scope presence and handle multiple devices; provide real-time read receipts; prove view-once at the media-access boundary; add media retention/cleanup and native upload/download E2E. Add edit-message semantics (author/time limit/tombstone, event ordering) only with a real contract and tests.
4. **P1 — social/recommendation quality.** First instrument privacy-aware impressions, dwell, hide/not-interested, follows, saves, cart and purchase conversions; define healthy engagement and avoid rewarding spam. Evaluate quality and stability across the 60-candidate ranking batches; test blocked authors, diversity, cold start and pagination. Then evaluate a versioned ranker with holdouts; do not add opaque weights before collecting a baseline.
5. **P2 — creator/seller and community depth.** Multi-image listing management, seller inventory/fulfillment console, listing and creator analytics, social report entry points, moderator workflow, user privacy/notification settings, and accessibility. Auctions, groups, live video, reels and advertising are separate products, not implied by a feed or chat route; prioritize based on real audience demand and support capacity.
