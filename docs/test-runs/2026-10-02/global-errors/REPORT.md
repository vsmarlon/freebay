# Global error recovery — 2026-10-02

**Revision:** `81e8866d980e2783dfe29a53b8eb7ca088e727f5` plus inherited dirty worktree and this scoped change. **Environment:** Windows, Flutter/Dart from the repository's configured FVM, no credentials or provider events. No device run.

## Finding and change

Root cause: `main` manually forwarded Flutter/platform errors to Sentry and then `SentryFlutter.init(appRunner:)` installed its own capture integrations, allowing one event to be captured twice. A second `ErrorReporter.run` around deferred service initialization also initialized Sentry again. Additionally, `ErrorWidget.builder` was installed only after storage/Hive initialization, and its fallback used `EmptyState.error`, which unconditionally queried localization and threw before a localization delegate existed.

Sentry now initializes once without owning/rerunning the app body; configured SDK integrations own error capture, while no-DSN handlers retain the fallback path. Raw error logs are debug-only. The widget error builder is installed before bootstrap awaits, uses generated localized copy with a generated-catalog fallback, and exposes a guarded retry action. Bootstrap failure displays a localized recovery screen and retries bootstrap; router errors provide back/root-feed recovery. A root fallback remounts the app with a fresh provider scope; persisted auth/storage is retained and no business mutation is replayed. In-memory drafts may be lost on this explicit recovery. No automatic rebuild is performed for ordinary asynchronous exceptions.
