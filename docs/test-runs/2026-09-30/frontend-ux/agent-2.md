# Frontend UX executor 2 handoff

**Revision:** `4558181` plus the existing dirty working tree and this executor's edits; no commit created. **Environment:** Windows, Flutter/Dart SDK from the checkout, no credentials used.

## Implemented

- Feed refresh keeps populated posts, uses `isRefreshing` separately from initial/pagination `isLoading`, reports errors without discarding posts, preserves stale-cache indication with `isStale`, and accepts only the latest request generation. Public Explore first-page cache is user-keyed; it excludes close-friends posts, signed/private media URLs, and account-secret user fields.
- Own-profile header first-paint provider restores only a minimal public-field projection for the authenticated user, emits `isStale`, then fetches the server. Profile and order detail calls remain server-fetched; profile/order family requests use Dio cancellation tokens.
- Purchases and unfiltered sales first pages restore user-keyed presentation cache, retain stale data on request failure, and expose `isRefreshing`/`isStale`. Cache values are serialized `OrderEntity` presentation data with nested user secrets stripped and signed media omitted. No cached value is used for order detail/actions or money state.
- Old Hive fallback was removed from `ProductRepository`; it now returns only HTTP results. `ProductsFeed` owns stale-first presentation caching, user fencing, signed-media filtering, account-safe seller projections, and the prior eight-filter-page cap held in a single versioned cache record.
- Save, repost, like, follow, and product-favorite actions now ignore duplicate same-key taps while pending, fence stale session responses, and guard failures. Likes/saves/reposts project one override source and reconcile only when a fresh entity matches it. An arbitrary-size eviction cap was removed because evicting an unreconciled successful mutation can flip visible state back to a stale entity value. Likes no longer mutate feed entities from its controller.
- Added shared `PaginatedState<T,C>` and `PageRequestGuard`; migrated post search, user search, profile timeline, and feed's request generation. Feed keeps its distinct explore/following mode semantics.
- Actual family HTTP requests that support Dio cancellation now cancel on disposal: profile header/details, profile timeline/user posts, follow status, order detail/review check, product detail/catalog pages.

## UI handoff

- Feed: `feedProvider` exports state with `isLoading`, `isRefreshing`, `isStale`, `error`, and `posts`. Use `isRefreshing` for a populated-list refresh indicator; show `error` non-blockingly while posts remain. `isStale` labels restored Explore content.
- Profile: consume `profileFirstPaintProvider(userId)` (`ProfileFirstPaint.user`, `.isStale`, `.error`) for cache-first own-header paint. Existing `profileFutureProvider` remains available and is auto-dispose.
- Orders: purchases/sales states expose `isRefreshing` and `isStale`; cached rows are presentation-only. Detail/actions must continue through `orderDetailProvider` server fetch.
- Cross-feature social action API is exported from `package:freebay/features/social/social.dart` (`likesProvider`, `savesProvider`, `repostsProvider`, `reconcileSocialPosts`). The duplicate feed mutation API/call sites are removed; UI reads the action projections.
