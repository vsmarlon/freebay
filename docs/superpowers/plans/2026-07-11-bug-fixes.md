## Task 1: Feed — Header black bar visible on scroll

**Bug:** The feed header leaves a black background bar when scrolling down. The header should hide (or collapse) when the user scrolls, so the feed occupies the full screen.

**Files to investigate:**
- `frontend/lib/features/social/presentation/pages/feed_page.dart`
- `frontend/lib/core/components/app_shell.dart` (check if the shell adds a persistent header)

- [ ] **Step 1: Read `feed_page.dart` and identify the header widget**

Note whether the header is inside a `SliverAppBar`, a plain `AppBar`, or a custom `Column` pinned above the `ListView`.

- [ ] **Step 2: Identify the background color issue**

The black bar usually means the `Scaffold` or `SliverAppBar` has `backgroundColor: Colors.black` (or the app theme default) showing through. Fix by either:
- Setting `backgroundColor: Colors.transparent` + `elevation: 0` on the `SliverAppBar`
- Using a `SliverAppBar(floating: true, snap: true)` to auto-hide the header on scroll
- If it is a `Column` layout, wrap in `CustomScrollView` with a `SliverAppBar(floating: true, pinned: false)`

- [ ] **Step 3: Implement the fix**

If the header is pinned with no scroll behavior, convert to `CustomScrollView` with:
```dart
CustomScrollView(
  slivers: [
    SliverAppBar(
      floating: true,
      snap: true,
      backgroundColor: context.bgColor,
      elevation: 0,
      toolbarHeight: <existing header height>,
      flexibleSpace: <existing header widget>,
    ),
    SliverList(delegate: SliverChildBuilderDelegate(...)),
  ],
)
```

- [ ] **Step 4: Flutter analyze**

```bash
cd frontend && fvm flutter analyze
```

- [ ] **Step 5: Commit**

```bash

git commit -m "fix(feed): hide header on scroll to eliminate black bar background"
```

## Task 8: Perfil — Follow/Unfollow: cannot re-follow after unfollow

**Bug:** After following then unfollowing a user, trying to follow again gives `Already following` (409).

**Log:**
```
ERROR POST /users/:id/follow - Already following
```

**Files to investigate:**
- `nest-backend/src/modules/users/data/repositories/follow-database.repository.ts`
- `nest-backend/src/modules/users/usecases/follow-user.usecase.ts`

- [ ] **Step 1: Check the follow repository's `follow` method**

Read `follow-database.repository.ts`. Look at the `follow` method — it likely does a Prisma `create` on a unique `[followerId, followingId]` pair. If the unfollow does a soft-delete (`isActive: false`) rather than a hard-delete, the unique record still exists.

- [ ] **Step 2: Check the unfollow method**

If `unfollow` sets `isActive = false` on the row instead of deleting it, then `follow` tries to create a new row, hits the unique constraint, and returns `Already following`.

- [ ] **Step 3: Fix**

**Option A** (preferred): Change `unfollow` to hard-delete the row. Then `follow` creates a fresh row each time.

**Option B**: Change `follow` to use `upsert` with `{ isActive: true }`.

Apply whichever matches the existing schema. If there is no `isActive` column, the bug is elsewhere — investigate further.

- [ ] **Step 4: Write regression test**

In the follow usecase spec, add:
```typescript
it('allows re-follow after unfollow', async () => {
  mockFollowRepository.isFollowing.mockResolvedValue(right(false));
  mockFollowRepository.follow.mockResolvedValue(right(undefined));
  // ... assert result.isRight()
});
```

- [ ] **Step 5: Typecheck + commit**

